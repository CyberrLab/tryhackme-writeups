# Security Monitoring and Log Analysis

## 1. Introduction

Security monitoring involves observing systems, applications, and network activity to identify suspicious behavior and potential security incidents.

Log analysis is the process of examining recorded events to understand system activity, investigate errors, and detect possible threats.

## 2. What Are Logs?

Logs are records of events generated by operating systems, applications, network devices, and security tools.

Common log types include:

- **System logs:** Record operating system events.
- **Authentication logs:** Record login attempts and authentication activity.
- **Application logs:** Record application events and errors.
- **Firewall logs:** Record network connections allowed or blocked by firewall rules.
- **Web server logs:** Record HTTP requests and responses.

## 3. Important Log Fields

A log entry may contain:

- Timestamp
- Source IP address
- Username
- Event type
- Severity level
- Status or result
- Message or description

These fields help analysts establish timelines and investigate suspicious activity.

## 4. Common Severity Levels

| Level | Meaning |
|---|---|
| DEBUG | Detailed diagnostic information |
| INFO | Normal operational events |
| WARNING | An unusual condition that may need attention |
| ERROR | An operation failed |
| CRITICAL | A severe problem requiring urgent attention |

Severity names and meanings can vary between applications.

## 5. Common Indicators to Investigate

Examples of activity worth investigating include:

- Repeated failed login attempts.
- Successful logins at unusual times or from unexpected locations.
- Unexpected privilege changes.
- Unfamiliar processes or services.
- Repeated firewall-denied connections.
- Unexpected changes to important files.
- Sudden increases in errors or unusual network traffic.

**Important:** One event alone does not prove an attack. Compare timestamps, users, systems, and related events before drawing conclusions.

## 6. Useful Linux Commands

Display recent system journal entries:

```bash
journalctl -n 50
```

Display authentication-related messages where the relevant log file exists:

```bash
sudo tail -n 50 /var/log/auth.log
```

On some Linux distributions, authentication logs are stored elsewhere or available through `journalctl`.

Search a text log for lines containing the word `failed`:

```bash
grep -i "failed" sample.log
```

Count the lines in a log file:

```bash
wc -l sample.log
```

Use these commands only on systems and logs you are authorized to access.

## 7. Log Analysis Workflow

1. Identify the system and log source.
2. Establish the time range being investigated.
3. Filter relevant events.
4. Group related events by user, IP address, or event type.
5. Correlate findings with other available evidence.
6. Record observations and preserve relevant evidence.
7. Recommend an appropriate response.

## 8. SIEM Fundamentals

A Security Information and Event Management (SIEM) system collects and analyzes security events from multiple sources.

Common SIEM capabilities include:

- Centralized log collection.
- Search and filtering.
- Event correlation.
- Alert generation.
- Dashboards and reporting.
- Investigation support.

Examples of security monitoring tools include Wazuh, Splunk, and Elastic Security.

## 9. Safe Practical Exercise

Create a sample log file on your own computer:

```bash
cat > sample.log <<'EOF'
INFO User login successful
WARNING Multiple failed login attempts
ERROR Application request failed
INFO Service started
EOF
```

Count and inspect the entries:

```bash
wc -l sample.log
cat sample.log
grep -i "failed" sample.log
```

Record how many entries exist and which lines match your search.

## 10. Key Takeaways

- Logs provide evidence of system and application activity.
- Authentication and firewall logs are useful during investigations.
- Filtering and correlating events help identify patterns.
- SIEM tools centralize monitoring and support alerting.
- Findings should be validated before declaring an incident.
- Preserve evidence and follow authorized investigation procedures.
